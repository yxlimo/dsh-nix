# dsh-nix

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`)
packaged for Nix from the published npm tarball, kept current by CI.

## Why a separate flake

`dsh` refuses to start on nixpkgs-built Node. Since 0.2.0 it reaches Node's
internal ESM loader through `node-addon-require-builtin`, a native addon that
decodes machine code inside the *running* `node` binary and only recognizes
nodejs.org builds. On a nixpkgs node every profile boot dies with:

```
Unsupported/no-getter (x64 sysv getter is not a recognized this->field accessor)
```

Upstream's own loader has an escape hatch — with `--expose-internals` set, a
plain `require(id)` resolves internals without the addon — but the published
`dsh` bin does not pass that flag.

This repository takes the npm tarball and **shadows the addon package**: the
module `node-addon-require-builtin` is replaced by a small shim that tries
`require(id)` first and delegates to the real addon (moved to
`node-addon-require-builtin-impl`) otherwise. The launcher wrapper passes
`--expose-internals`.

That is one substitution for all four call sites (`dsh-app-boot`, its worker
bootstrap, `cordis-plugin-loader`, `dsh-hmr`) instead of patching bundled
JavaScript, so a version bump cannot silently miss a fifth one. The build boots
a real profile in `installCheckPhase`, so any drift fails the build rather than
the deployment.

## Usage

```nix
{
  inputs.dsh-nix.url = "github:yxlimo/dsh-nix";
  inputs.dsh-nix.inputs.nixpkgs.follows = "nixpkgs";
}
```

```nix
# The package
environment.systemPackages = [ inputs.dsh-nix.packages.${pkgs.system}.dsh ];

# or the service module (runs `dsh web` as its own user)
imports = [ inputs.dsh-nix.nixosModules.default ];
services.dsh.enable = true;
```

Behind a mirror (the tarball bytes are identical, so the hash is unchanged):

```nix
(inputs.dsh-nix.packages.${pkgs.system}.dsh).override {
  registry = "https://registry.npmmirror.com";
}
```

`nix run github:yxlimo/dsh-nix` works without installing anything.

## What is packaged

| | |
| --- | --- |
| Version | the npm `latest` dist-tag, rewritten by CI (`packages/dsh.nix`) |
| Runtime | nixpkgs `nodejs_24`, plus `pnpm` on `PATH` for `dsh plugin` |
| Native addons | built from source during the build (`node-pty`, `koffi`) |
| Dependencies | `npm/package-lock.json`, generated by `scripts/gen-lock.py` |

The install check runs `dsh --version`, composes the web profile plugin tree
(`dsh web --dump-config`), and boots the server until it prints its
authenticated launch URL.

## Keeping it current

There is **no cron in this repository**. The polling lives in one place:
`gh-release-relay` on the Oracle box checks npm every 15 minutes and POSTs a
`repository_dispatch` to whichever packaging repo is behind. One timer serves
every packaging repo instead of each running its own schedule.

The workflow then regenerates the lockfile, recomputes the tarball hash, builds
and smoke-tests, and commits/tags. `workflow_dispatch` takes a version to force
a specific one.

Manual run:

```bash
python3 scripts/gen-lock.py 0.2.2-rc.1     # refresh npm/package-lock.json
nix build .#dsh                            # reports the tarball hash if it changed
```

## Layout

```
flake.nix                  packages / overlay / nixosModule
packages/dsh.nix           the derivation (version + tarball hash live here)
npm/                       package.json + package-lock.json for importNpmLock
scripts/gen-lock.py        regenerates npm/ from a published version
modules/dsh.nix            NixOS module: services.dsh
.github/workflows/update.yml
```
